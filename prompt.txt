FIRST STEP ONLY: build the backend notification infrastructure. Do NOT build frontend yet. Do NOT add email/push/WhatsApp yet.

Create an authenticated, user-scoped notification system.

Notification fields should support:

* id
* user_id
* type
* title
* message
* severity
* read/unread
* created_at
* optional related entity/type + related entity id
* optional metadata JSON if already supported safely

Initial notification types:

* budget_threshold
* budget_exceeded
* spending_velocity
* anomaly

Requirements:

* Every notification belongs to exactly one user.
* Users can only read/update/delete their own notifications.
* Add:
  GET /api/notifications
  PATCH /api/notifications/{id}/read
  PATCH /api/notifications/read-all
  DELETE /api/notifications/{id}
* Support unread count.
* Pagination for notification listing.
* Newest notifications first.
* Validate notification type/severity.
* Use existing authentication/security infrastructure.
* Do not expose another user's notifications.

IMPORTANT:

* Do NOT automatically generate notifications on every request.
* Do NOT add email.
* Do NOT add browser push.
* Do NOT add WhatsApp/SMS.
* Do NOT add Gemini.
* Do NOT change existing budget/velocity/anomaly algorithms yet.
* Avoid duplicate notifications for the same event.
* If an event identifier exists, use it for deduplication.
* Keep financial calculations deterministic.
